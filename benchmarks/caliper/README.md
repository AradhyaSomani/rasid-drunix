# RASID Caliper benchmark pack

Hyperledger Caliper workloads for the RASID registry, planned as an open
benchmark contribution to DRUNIX.

| Round | Measures |
|---|---|
| register-e-invoice | 200 TPS of IRP-signed registrations (signature check, uniqueness write, event) |
| month-end-spike | Linear ramp 100 → 1,000 TPS to find where latency breaks |
| check-duplicate | 1,000 TPS of read-only duplicate lookups |

Before running:

1. Deploy the chaincode and call `InitLedger` (`network/deploy-chaincode.sh`).
2. `go run ../../tools/mock-irp keygen -out keys` and register `keys/irp-public.pem`
   with `InvoiceRegistry:SetIRPPublicKey("irp-2026", ...)`.
3. Write a Caliper network config for your DRUNIX network with identities
   `supplier1` and `financier1` carrying the attributes noted in `benchmark.yaml`
   (the local one is generated by `networks/make-local.sh`).

```bash
npm install --no-save @hyperledger/caliper-cli@0.6.0
npx caliper bind --caliper-bind-sut fabric:fabric-gateway
npx caliper launch manager --caliper-workspace . \
  --caliper-networkconfig networks/drunix.yaml --caliper-benchconfig benchmark.yaml \
  --caliper-flow-only-test --caliper-fabric-gateway-enabled
```

For the local network in `network/local`, `bash networks/make-local.sh` writes
`networks/local.yaml`, and `benchmark-smoke.yaml` is a short version of the
rounds. A first local run (all 8,132 transactions succeeded) is in `results/`.

On DRUNIX, run each round twice, once with standard peers and once with lite
peers and the stateless validation service, and publish both reports.
